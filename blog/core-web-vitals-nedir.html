Core Web Vitals Nedir? LCP, INP ve CLS Nasıl İyileştirilir?

Google'ın sayfa deneyimi metrikleri LCP, INP ve CLS'nin anlamı, iyi kabul edilen eşik değerleri, ölçüm araçları ve pratik iyileştirme yöntemleri.

Core Web Vitals, Google'ın bir web sayfasındaki kullanıcı deneyimini ölçmek için kullandığı üç temel metriktir: yüklenme hızı, etkileşime yanıt verme ve görsel kararlılık. Bu metrikler hem arama görünürlüğünde bir sinyal olarak değerlendirilir hem de ziyaretçinin sitede kalıp kalmamasını doğrudan etkiler.

Üç metrik ve eşik değerleri

Metrik Neyi ölçer? İyi İyileştirilmeli Zayıf
LCP En büyük içeriğin yüklenme süresi ≤ 2,5 sn 2,5–4 sn > 4 sn
INP Etkileşimlere yanıt süresi ≤ 200 ms 200–500 ms > 500 ms
CLS Beklenmedik düzen kaymaları ≤ 0,1 0,1–0,25 > 0,25

Değerlendirme, gerçek kullanıcı verilerinin 75. yüzdelik dilimi üzerinden yapılır. Yani ziyaretlerin çoğunluğunda iyi deneyim sağlamanız gerekir.

LCP (Largest Contentful Paint)

Sayfadaki en büyük görsel veya metin bloğunun ekranda göründüğü süredir. Genellikle ana görsel (hero) veya büyük başlıktır.

İyileştirme yolları:

  • Ana görseli sıkıştırın ve WebP/AVIF gibi modern formatlarda sunun.
  • LCP görseline loading="lazy" eklemeyin; aksine fetchpriority="high" ile önceliklendirin.
  • Sunucu yanıt süresini (TTFB) kısaltın: önbellekleme, CDN ve hızlı hosting kullanın.
  • Render'ı engelleyen CSS ve JavaScript dosyalarını azaltın.
  • Web fontlarında font-display: swap kullanın.

INP (Interaction to Next Paint)

Mart 2024'te FID metriğinin yerini alan INP, kullanıcının tıklama, dokunma veya tuş basma gibi etkileşimlerinden sonra sayfanın görsel olarak yanıt vermesinin ne kadar sürdüğünü ölçer. FID'den farkı, yalnızca ilk etkileşimi değil sayfadaki tüm etkileşimleri dikkate almasıdır.

İyileştirme yolları:

  • Uzun süren JavaScript görevlerini küçük parçalara bölün.
  • Kullanılmayan üçüncü taraf betiklerini (sohbet widget'ları, fazla izleme kodu) kaldırın.
  • Ağır hesaplamaları Web Worker'lara taşıyın.
  • Olay dinleyicilerinde gereksiz DOM güncellemelerinden kaçının.
  • Büyük listelerde sanallaştırma veya sayfalama kullanın.

CLS (Cumulative Layout Shift)

Sayfa yüklenirken içeriğin beklenmedik şekilde kaymasını ölçer. Okumaya başladığınız metnin bir reklam yüklendiği için aşağı kayması tipik bir CLS sorunudur.

İyileştirme yolları:

  • Görsellere ve videolara width ve height değerleri verin.
  • Reklam ve gömülü içerikler için önceden alan ayırın.
  • Web fontlarının yüklenmesiyle oluşan kaymaları azaltmak için yedek font ölçülerini ayarlayın.
  • Mevcut içeriğin üstüne sonradan içerik eklemekten kaçının.

Nasıl ölçülür?

  • PageSpeed Insights: Hem laboratuvar verisi hem de (yeterli trafik varsa) gerçek kullanıcı verisi gösterir.
  • Search Console – Core Web Vitals raporu: Sitedeki sorunlu URL gruplarını listeler. Ayrıntılar için Search Console rehberi.
  • Chrome geliştirici araçları: Performance paneliyle yavaşlığın kaynağını satır satır inceleyebilirsiniz.
  • web-vitals kütüphanesi: Gerçek kullanıcı ölçümlerini kendi analiz aracınıza gönderebilirsiniz.

Laboratuvar verisi ile saha verisi

Lighthouse gibi araçlar kontrollü bir ortamda ölçüm yapar (laboratuvar verisi). Google'ın değerlendirmesi ise gerçek kullanıcılardan gelen saha verisine dayanır. İki veri farklı çıkabilir; karar verirken saha verisini esas alın.

Sık sorulan sorular

Core Web Vitals sıralamayı ne kadar etkiler?

İçeriğin alaka ve kalitesi hâlâ en belirleyici faktördür. Ancak benzer kalitedeki sayfalar arasında iyi sayfa deneyimi fark yaratabilir ve dönüşüm oranını doğrudan etkiler.

Skorum 100 olmak zorunda mı?

Hayır. Hedef, üç metrikte de "iyi" eşiğinin altında kalmaktır. Lighthouse puanı bir göstergedir, amaç değildir.

Sonuç

Core Web Vitals, kullanıcı deneyimini sayılarla ifade eder. LCP için hızlı yükleme, INP için hafif JavaScript, CLS için rezerve edilmiş alanlar temel kurallardır. Daha fazla öneri için web sitesi hızlandırma yazımıza göz atabilir, performans denetimi için bize ulaşabilirsiniz.
